# Платежи

- Источники: `clients/payments-client/src/main.rs` — HTTP и RPC; `model.rs` — целые суммы, состояния и JSON store; `verification.rs` — проверка compiled-транзакций; `web/` — интерфейс без отдельной сборки. Команды и API находятся в README клиента.
- Только Solana devnet и фиксированный USDC mint. При запуске обязательны проверка genesis, owner mint, initialized и decimals. Сервер никогда не читает ключи и не подписывает переводы.
- Модель MVP: один продавец, loopback, open/paid/closed, атомарная запись JSON и блокировка файла. Спецификация задания 13 описывает более широкий целевой продукт, а не текущий runtime.
- Создание, список и закрытие требуют bearer token. Он хранится только в памяти браузера; запрещены его вывод в логах, URL, API и документах. Сохраняйте Host/Origin проверки, CSP, запрет неизвестных полей и лимит тела запроса.
- Значения amount_raw — строки целых единиц, расчёт u64 без float. paid и квитанция возможны только после серверной проверки finalized RPC; данные клиента не подтверждают оплату.
- Reference должен присутствовать как readonly nonsigner именно в SPL-инструкции. Проверяйте mint, Token Program, канонический ATA, точные дельты и допустимые CPI. Неизвестный формат или неоднозначный перевод отправляется на ручную проверку.
- Ошибка RPC не равна отсутствию платежа. Ограничение поиска — 30 кандидатов и бюджет времени; превышение возвращает явную ошибку. Полная история и постоянный cursor не реализованы.
- После правок web пересобирайте crate из-за include_str. Проверки: fmt workspace, Clippy и tests payments-client; UI и реальный devnet read отдельно от контролируемых RPC fixtures. Реальные платежи не объявляйте выполненными по fixture-тесту.
